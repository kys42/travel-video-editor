# 토큰 효율적인 전수 장면 타임라인

## 목표

10일치 원본을 코덱스가 영상 그대로 순차 시청하지 않아도, 각 영상에 어떤 장면이 언제 있었는지 빠짐없이 탐색할 수 있게 합니다. 핵심 데이터 흐름은 다음과 같습니다.

```text
원본 → 기계 분석 → 전수 세그먼트 → 대표 이미지·음성 → 구조화 주석
     → 검색 가능한 타임라인 → 목적별 후보 → 편집 계획
```

`전수 세그먼트`와 `편집 후보`를 구분합니다. 모든 시간대는 전수 세그먼트에 포함되지만, 좋은 장면만 후보가 됩니다. 따라서 중요하지 않은 구간도 나중에 검색할 수 있고, 후보 수 제한 때문에 영상 후반부가 누락되지 않습니다.

## 데이터 단위

| 단위 | 역할 | 모델 호출 여부 |
|---|---|---|
| Asset | 원본 파일과 미디어 메타데이터 | 없음 |
| Sample | 저비용 프레임·오디오·품질 신호 | 없음 |
| Shot | 장면 전환 사이의 시각적 구간 | 없음 |
| Segment | 설명과 검색의 기본 구간 | 등급별 선택 |
| Annotation | 화면·대화·품질·위치 설명 | 일부 |
| Candidate | 편집에 쓸 가능성이 있는 구간 | 필요 시 상세화 |
| Edit Plan | 목적별 순서와 인·아웃점 | 최종 계획 시 사용 |

모든 단위는 `asset_id`, `start_ms`, `end_ms`로 원본에 역추적할 수 있어야 합니다.

## 1단계: 모델 없이 전수 분석

원본은 읽기 전용으로 스캔하고 다음 결과를 로컬 도구로 만듭니다.

- `ffprobe`: 코덱, 해상도, 프레임레이트, 촬영 시각, 길이, 오디오와 메타데이터
- FFmpeg: STT용 오디오, 일정 간격 프레임, 장면 전환 후보
- VAD/STT: 발화·무음 구간과 타임스탬프 전사
- 품질 신호: 암전, 정지, 노출, 흐림, 움직임, 음량
- 중복 신호: 파일 크기·빠른 지문·필요 시 전체 체크섬, 프레임 pHash
- 선택 사항: GPS, 자이로, OCR 후보

전체 720p 프록시는 첫 단계에서 만들지 않습니다. 원본 재생이 불편하거나 리뷰·렌더에 필요한 구간만 주문형으로 생성합니다. 이렇게 하면 시간과 디스크를 크게 줄일 수 있습니다.

## 2단계: 적응형 세그먼트

고정 간격만 사용하면 짧은 사건을 놓치고, 장시간 이동에서는 샘플이 과도하게 늘어납니다. 장면 전환, 움직임, 발화, 시간 간격을 함께 사용합니다.

- 행동·대화가 많은 구간: 약 5~12초
- 일반 풍경·관광 구간: 약 15~30초
- 변화가 적은 장거리 이동: 약 30~60초
- 매우 긴 단일 샷: 상한 길이에서 강제 분할

세그먼트는 원본 시간축을 겹침 없이 전부 덮도록 검증합니다. 장면 전환 탐지는 경계 제안일 뿐이며, 전환을 못 찾더라도 주기 샘플로 빈 구간을 방지합니다.

## 3단계: 대표 이미지와 연락판

각 세그먼트에서 시작·중간·끝 부근의 프레임을 추출한 뒤 선명도, 노출, 중복도를 비교해 1차 후보를 고릅니다. 기본 후보 위치는 20%, 50%, 80%입니다.

6~10개 세그먼트를 하나의 연락판으로 묶고 각 칸에 아래 값만 표시합니다.

- `segment_id`
- 원본 타임코드
- 품질 경고 아이콘

대사는 이미지에 길게 넣지 않고 별도의 짧은 구조화 텍스트로 전달합니다. 작은 한 장에 너무 많은 프레임을 압축하지 않습니다. 1차 리뷰에서 사건 그룹이 정해지면 그룹 내부의 시간 분포·시각적 차이·화질을 반영해 최대 12장 스토리보드를 만들고, 코덱스가 맥락 설명과 최종 대표 이미지를 다시 선택합니다.

## 4단계: 토큰 예산에 따른 분석 등급

### A — 상세 분석

사람, 대화, 큰 움직임, 독특한 장소, 높은 품질처럼 편집 가치가 높은 구간입니다. 코덱스에 연락판, 인접 STT, 기계 신호를 보내 상세 설명과 역할 후보를 받습니다.

### B — 대표 분석

비슷한 풍경이나 이동 장면은 시각 임베딩·pHash·품질 신호로 묶고 군집 대표만 분석합니다. 나머지는 `representative_segment_id`와 상속된 태그를 갖되 `inferred`임을 표시합니다.

### C — 기계 분석만

렌즈 가림, 암전, 극심한 흔들림, 장시간 무변화, 명확한 중복처럼 가치가 낮은 구간입니다. 모델 호출 없이도 타임라인에는 남깁니다.

분석 등급은 나중에 바꿀 수 있습니다. 사용자가 C 구간을 검색하거나 선택하면 해당 구간만 A로 승격해 다시 분석합니다.

## 모델 입력 계약

모델에는 원본 전체가 아니라 다음의 제한된 묶음만 전달합니다.

```json
{
  "batch_id": "day03-sheet-004",
  "segments": [
    {
      "segment_id": "A0123-S004",
      "start_ms": 43000,
      "end_ms": 51800,
      "keyframe_cells": ["B2", "B3"],
      "transcript_candidates": {
        "ko": "여기서 배를 타는 것 같아",
        "en": "I think we take the boat here"
      },
      "signals": {"motion": 0.71, "blur": 0.08, "speech": true}
    }
  ]
}
```

응답은 자유 형식 설명 대신 스키마로 제한합니다.

```json
{
  "segment_id": "A0123-S004",
  "visual_summary": "선착장에서 일행이 배에 오르기 직전 대화한다",
  "actions": ["걷기", "탑승 준비"],
  "subjects": ["동행자", "선착장", "배"],
  "scene_roles": ["transition", "travel_context"],
  "importance": 0.76,
  "privacy_flags": [],
  "confidence": 0.84
}
```

ID와 타임코드는 모델이 새로 만들지 못하게 하고 입력값과 일치하는지 검증합니다. 잘못된 ID, 범위를 벗어난 타임코드, 누락된 응답은 저장하지 않고 재시도합니다.

## 계층형 요약

상위 요약에서 이미지와 긴 전사를 다시 보내지 않습니다.

```text
세그먼트 설명 → 파일 요약 → 하루 요약 → 여행 전체 요약
```

파일 요약은 세그먼트 JSON만, 하루 요약은 파일 요약만, 여행 요약은 하루 요약만 사용합니다. 단, 최종 후보를 고를 때는 해당 세그먼트의 대표 이미지와 원문 전사를 다시 확인합니다.

## 캐시와 재현성

각 단계의 캐시 키는 `source_fingerprint + stage_version + config_hash`로 만듭니다. 결과 파일은 임시 이름으로 완성한 뒤 원자적으로 교체합니다. 원본이 같고 설정이 변하지 않았다면 재실행 시 건너뜁니다.

카탈로그에는 분석 모델·프롬프트·도구 버전과 `observed`, `inferred`, `human_verified` 상태를 함께 저장합니다. 자동 추론과 실제 관찰을 구분해야 나중에 잘못된 군집 상속을 고칠 수 있습니다.

## 사람에게 보여줄 타임라인

최소 리뷰 화면은 다음 정보를 시간순으로 표시합니다.

- 대표 이미지와 짧은 장면 설명
- 시작·종료 타임코드와 원본 재생 링크
- STT/OCR 일부
- 움직임·흐림·노출·음량
- 중복·개인정보 경고
- 선택, 제외, 별점, 메모

필터는 날짜, 장소, 인물, 행동, 발화, 품질, 분석 등급, 공개 가능 여부를 지원합니다. 타임라인에서 선택한 세그먼트만 상세 분석하거나 리뷰 프록시를 생성할 수 있게 합니다.

## 파일럿 합격 조건

- 원본 시간축 누락이 0인지 자동 검증
- 임의 세그먼트가 정확한 원본 타임코드로 열리는지 확인
- 말 없는 중요 장면도 검색되는지 확인
- 같은 장면 반복 촬영을 군집화하되 원본 관계를 잃지 않는지 확인
- 모델이 직접 보는 이미지 수와 입력 토큰을 기록
- 재실행 시 완료된 단계가 캐시되는지 확인
- A/B/C 샘플 각각의 설명 정확도를 사람이 평가
