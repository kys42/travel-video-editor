# 권장 아키텍처

## 설계 목표

- 수십~수백 GB 원본을 모델 컨텍스트에 직접 넣지 않는다.
- 원본과 파생 자료를 명확히 분리한다.
- 음성이 없는 풍경·이동·액티비티 장면도 검색할 수 있어야 한다.
- 모든 AI 판단을 파일과 타임코드로 검증할 수 있어야 한다.
- 같은 색인에서 개인 소장용과 공개용 결과를 다르게 만들 수 있어야 한다.
- 특정 NLE를 바꾸더라도 분석 결과를 재사용한다.
- 원본 전체 시간축을 색인하되 코덱스가 직접 보는 자료는 대표 샘플로 제한한다.
- 전수 세그먼트와 편집 후보를 분리한다.

상세한 세그먼트·연락판·토큰 예산 규칙은 [토큰 효율적인 전수 장면 타임라인](token-efficient-scene-timeline.md)에 정의합니다.

## 처리 흐름

```text
[원본 미디어: 읽기 전용]
          |
          v
[인벤토리]
경로, 크기, 해시, 촬영시각, 코덱, 길이, 카메라, GPS
          |
          v
[저비용 파생 자료]
16kHz mono 음성 / 장면 경계 / 대표 프레임 / 품질 신호
          |
          v
[전수 세그먼트]
모든 시간대를 검색 가능한 구간으로 분할
          |
          v
[등급별 멀티모달 분석]
STT / 연락판 / 장면 설명 / OCR / 위치 / 품질 / 중복
          |
          v
[카탈로그]
SQLite + JSONL + HTML 검토 화면
          |
          v
[편집 후보]
목적별로 가치 있는 세그먼트 선택
          |
          v
[편집 계획]
클립 ID, source in/out, 역할, 이유, 크롭, 오디오, 순서
          |
          +---------------------+
          |                     |
          v                     v
[FFmpeg 미리보기]       [OTIO/FCPXML/EDL]
                                |
                                v
                     [Resolve/Premiere/Final Cut]
```

## 저장소 경계

### 원본 루트

- 프로젝트 저장소 밖에 위치
- 읽기 전용 취급
- 원본 이름 변경과 폴더 재구성 금지
- 인벤토리에는 절대 경로와 안정적인 `asset_id`를 함께 기록
- 필요하면 SHA-256보다 빠른 콘텐츠 지문과 별도 보존용 체크섬을 구분

### 프로젝트 저장소

- 코드, 설정, 문서, 스키마
- 작은 JSONL/CSV/SQLite 메타데이터
- Git으로 추적 가능한 자료

### 작업 미디어 루트

- 프록시, WAV/M4A, 프레임, 연락판, 미리보기
- 삭제 후 재생성 가능
- 외장 SSD 사용 권장
- 원본과 다른 디렉터리에 배치

## 파이프라인 단계

### 1. 인벤토리

`ffprobe`를 사용해 다음 필드를 수집합니다.

- 절대 경로와 상대 경로
- 파일 크기와 수정 시각
- 촬영 시각
- 영상·오디오 코덱
- 해상도, 회전, 프레임레이트, 비트레이트
- 재생 시간
- 오디오 채널과 샘플레이트
- 카메라·렌즈·GPS 메타데이터

결과: `catalog/assets.jsonl`, `catalog/assets.csv`

### 2. 프록시와 음성

권장 초기값:

- 프록시: 전체 선생성하지 않고 상세 검토·미리보기에 필요한 구간만 주문형 생성
- 음성: 16 kHz mono, STT에 적합한 압축 형식
- 프레임: 촬영 특성에 따라 5~15초마다 추출
- 장면 대표 프레임: 시작·중간·끝 또는 탐지된 장면당 1~3장

주문형 프록시의 초기 후보는 1280x720, 원본 화면비 보존, H.264입니다. 정확한 코덱과 비트레이트는 파일럿에서 화질·속도·용량을 비교한 뒤 확정합니다.

### 3. 음성 분석

- 언어 탐지 또는 예상 언어 힌트
- 타임스탬프가 포함된 원문 전사
- 필요 시 화자 라벨
- 장소명·인명·고유명사 사전
- SRT/VTT 생성
- 발화 구간과 무음 구간 기록

STT 결과를 후처리할 때 원문을 임의로 재작성하지 않고, 교정본과 원 전사를 분리합니다.

### 4. 영상 분석

- 장면 전환 탐지
- 주기별 대표 프레임 설명
- OCR: 간판, 메뉴, 역명, 표지판
- 사람이 보이는지, 셀피인지, 풍경인지
- 실내/실외, 낮/밤, 날씨 추정
- 흐림, 과노출, 암부, 렌즈 가림
- 움직임과 흔들림 정도
- 세로 크롭 가능성

장면 설명은 원본 전체가 아니라 대표 프레임과 인접 STT를 함께 사용해 생성합니다.

### 5. 검색 카탈로그

초기 구현은 SQLite와 JSONL로 충분합니다.

- 구조화 필터: 날짜, 위치, 카메라, 사람, 길이, 품질
- 전문 검색: STT, OCR, 장면 설명
- 선택적 임베딩 검색: 의미가 비슷한 장면 탐색
- HTML 연락판: 썸네일, 재생 링크, 별점, 보류/제외 표시

### 6. 편집 계획

내부 편집 계획의 최소 필드:

```json
{
  "sequence_id": "youtube-main-v01",
  "items": [
    {
      "asset_id": "D04_CAM01_0032",
      "source_in": 43.2,
      "source_out": 51.8,
      "role": "opening_broll",
      "reason": "시장 전경과 일행 반응이 함께 보임",
      "crop": "16:9",
      "audio": "ambient",
      "confidence": 0.86
    }
  ]
}
```

LLM이 타임코드를 자유 텍스트로만 출력하지 못하게 스키마 검증을 적용합니다.

### 7. 출력

- 저용량 리뷰 MP4
- 선택 목록 CSV/JSON
- 한국어·영어 SRT/VTT
- OpenTimelineIO
- 필요 시 FCPXML 또는 EDL
- YouTube 제목·설명·챕터 초안
- Shorts/Reels용 9:16 후보
- 썸네일 후보 이미지

## 출력 프로필

### 개인 소장용

- 날짜와 이동 순서 우선
- 주변음과 대화의 맥락 보존
- 인물과 동행자의 등장 비중 확대
- 장면 길이를 비교적 길게 유지
- 하루별 챕터와 전체 여행 장편판 제작

### YouTube 본편

- 초반 15~30초 훅
- 이동 목적과 사건의 흐름 중심
- 반복·무음·준비 구간 압축
- 자막, 챕터, 개인정보, 음악 권리 검토
- 가로 16:9 기준 편집

### Shorts/Reels

- 15~60초 독립 서사
- 세로 크롭 가능성 점수 사용
- 화면 중심 피사체와 짧은 발화 우선
- 큰 자막과 안전 영역 적용

## 검토 게이트

1. 원본 인벤토리 검토
2. 프록시 품질과 저장 용량 검토
3. STT와 대표 프레임 샘플 정확도 검토
4. 자동 추천 클립 검토
5. 러프컷 검토
6. 얼굴·번호판·사적 대화·음악 권리 검토
7. 최종 렌더 또는 공개 업로드 승인

최종 업로드, 원본 삭제, NLE 프로젝트 덮어쓰기는 자동화 범위에 포함하지 않습니다.
