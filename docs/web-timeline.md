# 재사용 가능한 웹 타임라인

## 목적

최종 장면 JSON을 사람이 빠르게 훑고 필요한 부분만 깊게 검토하는 로컬 웹으로 변환합니다. 한 화면에 모든 정보를 노출하지 않고 `사건 요약 → 특이 포인트 → 편집 판단 → 기계 근거` 순서로 단계적으로 보여 줍니다.

주 사용 환경은 1280px 이상의 데스크톱 편집 워크스테이션입니다. 좌측 사건 인덱스, 상단 공용 미리보기와 다열 편집 판단 행의 정보 밀도를 데스크톱에 맞춥니다. 모바일은 공유된 결과를 열람할 수 있는 반응형 호환 계층으로 유지하지만 제품 판단과 시각 검증의 기준은 데스크톱입니다.

## 실행

```bash
uv run travel-video render-web timeline.context-reviewed.json \
  --output-dir web
```

영상 단위 종합이 끝난 `timeline.summarized.json`을 입력하면 같은 상세 화면 상단에 `VIDEO SYNOPSIS` 밴드가 추가됩니다.

```bash
uv run travel-video render-web timeline.summarized.json \
  --output-dir web
```

현재 명령은 영상 인코딩이나 복사를 하지 않습니다. 기본값에서는 검토용 프레임을 HTML에 내장하므로 Codex 리모트, 다운로드한 파일, 다른 로컬 경로에서도 `index.html` 하나만으로 이미지를 볼 수 있습니다. 결과는 다음 두 파일이 핵심입니다.

```text
web/
├── index.html      # CSS, JavaScript와 검토 프레임을 포함한 오프라인 단일 페이지
└── manifest.json   # 입력 타임라인과 렌더 설정
```

같은 컴퓨터의 고정된 폴더 구조에서만 사용하고 HTML 용량을 줄이고 싶다면 아래처럼 기존 Phase 1 프레임을 상대 경로로 참조할 수 있습니다.

```bash
uv run travel-video render-web timeline.context-reviewed.json \
  --output-dir web \
  --assets relative
```

`manifest.json`에는 `asset_mode`, 내장한 고유 이미지 수와 원본 바이트 수를 기록합니다. 내장 모드는 같은 이미지를 디스크에서 한 번만 읽지만 HTML 여러 위치에서 같은 data URL을 사용할 수 있으므로 최종 HTML 크기는 원본 이미지 합계보다 커질 수 있습니다.

## 화면 구조

1. 파일명, 길이, 사건 수와 원본 기술 정보를 보여 주는 헤더
2. 요약 데이터가 있으면 영상 제목·전체 서사·시간순 사건을 보여 주는 `VIDEO SYNOPSIS`
3. 사건 제목을 세로로 나열한 전체 타임라인
4. 장소·행동·대화 내용을 찾는 로컬 검색
5. 현재 선택한 사건을 따라오는 상단 공용 미리보기 덱
6. 장면을 펼쳤을 때 나타나는 사건 설명과 원본 기준 구간 정보
7. 솔직한 순간·살릴 대사·돌발 상황·그림 되는 컷·여행 디테일과 편집 활용도를 보여 주는 특이 포인트
8. 5~30초 세부 구간마다 화면·행동, 음성·이중 STT, 품질과 편집 제안을 합친 편집 판단 타임라인
9. 최대 16장의 시간순 프레임, 대표 프레임과 핵심 순간
10. 화면 맥락과 STT를 종합한 대화 요약
11. 필요할 때만 펼치는 한국어·영어 STT 원문 후보

## Review Workspace와 Rough Cut

다중 영상 라이브러리가 생성하는 `index.html`에는 영상 목록과 장면 타임라인을
묶은 `Review Workspace`가 하나만 존재합니다. Review와 Rough Cut은 이 DOM을
복사하지 않고 같은 검색, 영상 선택, 장면 펼침, 다중 선택, 프록시 seek 상태를
그대로 공유합니다.

- Review: `Review Workspace + Source Monitor`
- Rough Cut: `Review Workspace + Revision + AI Editor`

서버에서는 `/`와 `/rough-cut`이 같은 생성 문서를 제공합니다. 브라우저 모드가
바깥 패널 배치만 전환하므로 Review의 장면 정보나 동작을 수정하면 Rough Cut에도
자동으로 반영됩니다. 오프라인 파일에서는 `?mode=review`와
`?mode=rough-cut`으로 같은 전환을 사용합니다.

에이전트가 `edit_revision_ref` 카드를 보내면 가운데 Revision 패널은 원본 장면
ID를 가진 클립 목록을 구성합니다. 클립을 누르면 공용 Review Workspace가 해당
영상으로 전환하고 연결 장면을 펼쳐 원본 근거와 STT를 즉시 검토할 수 있습니다.
클라이언트는 마지막 revision 카드를 세션 저장소에 보존하지만 편집의 권위 있는
상태는 계속 SQLite revision과 서버 도구 계약입니다.

편집 제안은 `우선 유지`, `선별 사용`, `짧게 연결`, `축약·제외` 네 상태입니다. 핵심 순간, 중요도, 장면 유형과 기계 품질 경고로 만든 검토 우선순위이며 자동 컷 확정이 아닙니다. 사용자는 같은 행에서 실제 행동과 전사 후보를 함께 보고 구간 길이를 판단할 수 있습니다.

특이 포인트는 사건 요약을 과장하지 않도록 별도 데이터로 둡니다. 그룹당 0~3개이며 실제로 편집 가치가 있을 때만 생성합니다. 모든 항목은 스토리보드 후보 프레임에 연결되고 `category`, `title`, `description`, `edit_hint`를 가집니다. 웹에서는 상단 특이 포인트 카드, 해당 편집 판단 행과 장면 흐름의 프레임 배지에 같은 근거를 반복 표시합니다.

HTML 템플릿은 `src/travel_video/templates/timeline.html`, 데이터 조합과 검증은 `src/travel_video/web.py`에 분리했습니다. 다른 여행이나 다른 카메라에도 같은 최종 JSON 스키마를 입력하면 동일한 웹을 만들 수 있습니다.

여러 `timeline.summarized.json`을 파일 단위로 나열하는 상위 템플릿은 `src/travel_video/templates/library.html`과 `src/travel_video/library.py`에 분리했습니다. 자세한 흐름은 [영상 단위 요약과 다중 영상 라이브러리](video-library.md)를 참고합니다.

## 이미지 밀도

1차 추출은 전체 영상을 5초 간격으로 샘플링합니다. 사건 그룹의 2차 스토리보드는 기본 최대 12장이고, 그 이하이면 해당 그룹의 5초 샘플을 모두 포함합니다. 웹 상세는 최대 16장까지 표시합니다.

2초 간격 보강은 다음 조건에만 적용할 예정입니다.

- 그룹이 길어 5초 샘플 사이 사건을 놓칠 가능성이 큼
- 시각 변화량이 높은 구간이 연속됨
- STT에 중요한 대사가 있지만 대응 프레임이 불명확함
- 사용자가 별표를 주거나 편집 후보로 선택함

이 보강 자료도 기존 그룹에 추가할 뿐 전체 분석을 다시 실행하지 않습니다.

## 프록시와 4K 원본의 역할

프록시가 추가되더라도 시간 좌표의 기준은 항상 원본입니다.

```text
4K 원본
  ├─ 같은 시작점·길이의 저화질 프록시 → 분석, 검토, 구간 재생
  └─ asset_id + source_in + source_out → 최종 컷·자막·효과 적용
```

프록시 생성은 웹 렌더와 분리된 단계로 둡니다. 여러 리포트를 고쳐도 인코딩이 반복되지 않습니다. 프록시를 연결하면 장면마다 플레이어를 반복하지 않고 상단 공용 미리보기 덱 한 곳만 `<video>`로 전환합니다. 사건·세부 구간·프레임의 타임코드 버튼은 이 플레이어를 해당 원본 좌표로 이동시키고 구간 끝에서 멈춥니다. 데스크톱에서는 같은 덱을 우측 상단 PIP처럼 고정하는 변형도 가능하지만 재생 상태는 하나만 유지합니다.

## 향후 Codex 스킬 구조

프로세스가 안정되면 스킬은 다음 순서를 실행하는 얇은 오케스트레이터로 만듭니다.

1. FFmpeg, MLX Whisper와 저장 공간 확인
2. `phase1` 실행 또는 캐시 재사용
3. 1차 연락판을 보고 `timeline.review.json` 작성·검증
4. 사건별 스토리보드를 보고 대표 프레임·맥락·특이 포인트가 포함된 `context-review.json` 작성·검증
5. 장면 결과만으로 영상 전체 요약을 생성·검증
6. `render-web`과 필요 시 `render-library` 실행
7. 결과 링크와 처리 통계 보고

스킬 안에 분석 알고리즘이나 HTML을 복사하지 않습니다. 스킬은 프로젝트 CLI를 호출하고, 이미지 해석이 필요한 두 리뷰 단계에서만 Codex 판단을 사용합니다. 따라서 다른 워크스페이스에서도 저장소 경로와 입력 영상만 지정해 같은 절차를 재사용할 수 있습니다.
