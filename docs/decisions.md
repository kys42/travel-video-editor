# 결정 기록과 미결 사항

## 확정된 초기 결정

### D-001: 로컬 우선으로 시작

상태: 채택

원본을 외부 서비스에 먼저 업로드하지 않습니다. 인벤토리, 프록시, 음성, 대표 프레임과 기본 색인을 로컬에서 생성합니다. VideoDB나 OpenAI API는 파일럿 결과에 따라 선택적으로 사용합니다.

### D-002: 원본 불변

상태: 채택

원본 영상은 읽기 전용으로 취급합니다. 파생 자료와 출력은 별도 디렉터리에 생성하며 원본 파일 이름 변경, 덮어쓰기, 삭제를 자동화하지 않습니다.

### D-003: STT 단독 색인 금지

상태: 채택

여행 영상은 말이 없는 풍경과 행동이 중요하므로 음성 전사, 대표 프레임, OCR, 촬영 시각, GPS와 품질 지표를 함께 사용합니다.

### D-004: 편집 계획은 구조화 데이터로 보존

상태: 채택

편집 추천은 자유 텍스트만으로 남기지 않습니다. 모든 클립을 `asset_id`, `source_in`, `source_out`, 역할, 선택 이유와 함께 JSON으로 저장하고 OTIO/FCPXML/EDL로 내보낼 수 있게 합니다.

### D-005: MCP는 선택 사항

상태: 채택

초기 파일럿은 직접적인 로컬 도구로 수행합니다. FFmpeg MCP, Resolve MCP, VideoDB MCP는 반복성과 편집기 제어 필요성이 확인된 뒤 도입합니다.

### D-006: 파일럿 우선

상태: 채택

10일치 전체 배치 전에 하루치 또는 30~60분의 다양한 촬영 조건으로 파이프라인을 검증합니다.

### D-007: 전수 타임라인과 편집 후보 분리

상태: 채택

원본의 모든 시간대는 세그먼트 타임라인에 포함합니다. 편집 후보는 그 타임라인에서 파생하며, 후보 개수 제한 때문에 원본의 일부가 검색 불가능해지지 않게 합니다.

### D-008: 모델 호출을 A/B/C 등급으로 제한

상태: 채택

고가치 구간은 상세 분석하고, 반복 구간은 군집 대표만 분석하며, 명백한 불량·중복 구간은 기계 분석만 유지합니다. 사용자가 요청한 구간은 나중에 상세 등급으로 승격할 수 있습니다.

### D-009: 초기 색인은 전체 프록시에 의존하지 않음

상태: 채택, 운영 정책은 D-026으로 확장

초기 색인은 오디오, 대표 프레임, 장면 경계와 품질 신호만으로도 만들 수 있어야 합니다. 프록시 생성 여부 때문에 타임라인 분석이 막히지 않습니다. 현재 프로젝트의 전체 1080p 작업 프록시 정책은 D-026을 따릅니다.

### D-010: 모델 입출력은 ID 기반 스키마로 제한

상태: 채택

코덱스에는 연락판, 기존 세그먼트 ID, 제한된 STT와 기계 신호만 제공합니다. 응답의 ID와 타임코드는 입력과 대조하고 자유롭게 만든 범위는 거부합니다.

### D-011: 한국어·영어 STT 후보를 항상 함께 보존

상태: 채택

한국어와 현지 영어가 섞인 여행 영상은 전체 음성을 한국어와 영어로 각각 전사합니다. 기계 점수만으로 한 후보를 삭제하지 않고 장면별로 두 후보를 함께 보존하며, 코덱스가 화면 맥락과 함께 대화 내용을 종합합니다. 언어별 전사는 독립적으로 캐시합니다.

### D-012: 장면 설명과 대표 이미지는 2차 스토리보드로 확정

상태: 채택

1차 연락판은 시간축을 나누고 사건 그룹을 만드는 데 사용합니다. 그룹이 정해지면 내부에서 시간 분포, 시각적 차이와 화질을 반영한 최대 12장 스토리보드를 만들고, 코덱스가 전체 맥락 설명·핵심 순간·최종 대표 이미지를 다시 선택합니다. 기계가 고른 한 장을 최종 대표로 간주하지 않습니다.

### D-013: 웹 리포트는 영상 없이 즉시 생성

상태: 채택

기본 웹 산출물에는 원본이나 프록시 영상을 포함하지 않습니다. 공용 미리보기 덱과 원본 기준 `start/end`만 유지해 리포트 렌더는 즉시 끝나게 합니다. 프록시 생성은 별도의 캐시 가능한 미디어 단계로 분리합니다.

### D-014: 프록시에서 판단하고 원본에 편집 적용

상태: 채택

저화질 프록시는 분석·검토·미리보기 용도입니다. 프록시는 원본과 같은 시작점과 길이를 유지하고, 모든 결정은 `asset_id + source_in + source_out`으로 저장합니다. 최종 컷, 자막과 효과는 이 좌표를 4K 원본에 적용해 렌더합니다.

### D-015: Codex 스킬은 코어 CLI의 얇은 실행 계층

상태: 채택

처리, 검증과 웹 렌더 로직은 일반 CLI와 JSON 계약에 둡니다. 완성 후 만드는 Codex 스킬은 환경 확인, 명령 실행, 연락판·스토리보드 해석과 구조화 리뷰 작성을 순서대로 오케스트레이션합니다. 이렇게 해야 스킬 설치 위치와 무관하게 같은 프로젝트를 재사용하고 테스트할 수 있습니다.

### D-016: 웹 검토 프레임은 기본적으로 HTML에 내장

상태: 채택

Codex 리모트나 다른 컴퓨터에서 상대 경로가 끊겨 이미지가 보이지 않는 문제를 피하기 위해 `render-web`의 기본 자산 모드는 `embed`로 둡니다. 고정된 로컬 디렉터리에서 용량을 줄여야 할 때만 `--assets relative`를 선택합니다. 영상은 내장 대상이 아닙니다.

### D-017: 영상 플레이어는 리포트 전체에 하나만 유지

상태: 채택

각 사건 안에 영상 플레이어를 반복하면 긴 타임라인의 정보 밀도와 스캔 속도가 떨어집니다. 현재는 상단 공용 미리보기 덱만 두고, 프록시가 준비되면 이 위치의 단일 플레이어 또는 데스크톱 PIP로 재생합니다. 모든 타임코드 동작은 같은 플레이어를 제어합니다.

### D-018: 행동과 음성을 같은 편집 판단 행에 결합

상태: 채택

세부 구간마다 원본 `start/end`, 대표 프레임, 화면·행동 해석, 한국어·영어 STT 후보, 무음·품질 신호와 편집 제안을 함께 표시합니다. 제안 상태는 검토 우선순위일 뿐 자동 컷 확정이 아니며, 실제 결정은 시청 확인 후 원본 좌표에 기록합니다.

### D-019: 사실 요약과 특이 포인트를 분리

상태: 채택

사건 전체를 설명하는 `narrative_summary`는 사실 중심으로 유지하고, 웃긴 반응·돌발 상황·시각적으로 강한 컷·살릴 대사·여행 디테일은 `notable_moments`로 별도 기록합니다. 특이 포인트는 그룹당 최대 3개이고 기존 2차 스토리보드 후보 프레임에 반드시 연결해야 합니다. 별도 모델 패스를 추가하지 않으며 실제 편집 가치가 없으면 빈 목록을 허용합니다.

### D-020: 웹 리포트는 데스크톱 우선

상태: 채택

주 사용자는 긴 영상을 검토하고 편집 구간을 정하는 데스크톱 사용자입니다. 1280px 이상에서 좌측 사건 인덱스, 공용 미리보기와 다열 판단 행의 정보 밀도를 우선 최적화합니다. 모바일은 결과 열람을 위한 반응형 호환 계층이며 제품 UX의 기준 뷰포트로 사용하지 않습니다.

### D-021: 영상 전체 요약은 검토 완료 장면에서만 합성

상태: 채택

영상 단위 제목, 한 줄 설명, 전체 서사와 시간순 사건은 `timeline.context-reviewed.json`의 장면 설명·대화·특이 포인트만 입력으로 사용합니다. 원본 영상, 연락판과 스토리보드를 다시 모델에 전달하지 않습니다. 모든 장면 그룹이 원래 순서대로 한 번씩 포함됐는지 검증하고 대표 프레임도 기존 검토 후보 안에서만 선택합니다.

### D-022: 다중 영상 인덱스는 촬영 메타데이터순으로 렌더

상태: 채택

여러 영상은 MP4 `creation_time`과 원본 파일명으로 안정 정렬합니다. 메타데이터가 UTC이면 화면에 UTC를 명시하며 별도 근거 없이 현지 시각으로 변환하지 않습니다. 인덱스는 파일별 대표 프레임 하나와 요약만 내장하고 상세 프레임·행동·대화는 개별 타임라인으로 연결합니다. 다중 영상 렌더 자체에는 모델 호출이 없습니다.

### D-023: 단계 데이터와 판단 계보를 손실 없이 보존

상태: 채택

원시 도구 응답, 정규화 레코드, 시간 정렬, 필터 판정, AI 종합, 사람 수정과 표시용 출력을 서로 다른 단계로 저장합니다. 후속 단계는 이전 결과를 덮어쓰지 않으며 모든 레코드는 입력 ID, 실행 설정, 모델·프롬프트·규칙 버전과 채택·제외 이유를 통해 원본까지 역추적할 수 있어야 합니다. 필터링은 삭제가 아니라 판정 데이터입니다. 작은 구조화 데이터와 실행 manifest는 장기 보존하고, WAV·프록시·프레임 같은 대용량 파생 미디어만 재생성 가능한 캐시로 관리합니다.

### D-024: 혼합 언어 STT는 구간별 라우팅과 선택적 이중 전사를 사용

상태: 파일럿 채택

영상 전체에 언어 하나를 자동 선택하지 않습니다. VAD 경계와 최대 길이 창마다 언어 확률을 계산하고 확실한 구간은 해당 언어로만 전사합니다. 확률이 낮거나 언어 경계에 인접한 구간은 예상 언어를 모두 전사하며, 복수 후보가 필터를 통과하면 실제 언어를 자동 확정하지 않고 `mixed_or_uncertain`으로 남깁니다. 현재 FFmpeg 에너지 VAD는 시끄러운 장소에서 실제 발화를 충분히 분리하지 못하므로 교체 가능한 초기 백엔드로 취급하고, Apple SpeechDetector 또는 신경망 VAD·화자 턴 탐지를 A/B 검증합니다.

### D-025: Apple STT는 SpeechDetector를 필수 모듈로 사용

상태: 파일럿 채택

Apple `SpeechTranscriber`를 실행할 때 항상 `SpeechDetector`를 같은 `SpeechAnalyzer`에 넣고 기본 감도는 `medium`으로 둡니다. Transcriber는 로케일별로 한국어·영어를 독립 실행하며 원시 결과, 대안, 구절별 시간과 신뢰도를 모두 보존합니다. 현재 macOS 26 API에서 Detector 결과 스트림은 오류 보고만 지원하므로 빈 `detector_results`를 “Detector 미사용”으로 해석하지 않습니다. 외부 검토용 활동 범위는 양쪽 전사 타임스탬프 합집합으로 파생하고 그 출처를 명시하며, 독립 raw VAD 경계가 필요한 경우에는 신경망 VAD를 병렬로 사용합니다.

### D-026: T7 원본과 ExternalSSD 작업 프록시를 분리

상태: 채택

4K·카메라 원본은 `/Volumes/T7/시애틀알래스카`에서 읽기 전용으로 유지합니다. 분석·검토·웹 재생용 1080p H.264 프록시는 `/Volumes/ExternalSSD/travel-video-editor/proxies/1080p-h264`에 원본 상대 경로를 미러링해 일괄 생성합니다. 프록시에서 내린 모든 판단은 원본 타임코드로 저장하며 최종 편집과 렌더에는 T7 원본을 다시 연결합니다. 프록시는 재생성 가능한 캐시이고 manifest와 편집 결정은 보존합니다.

### D-027: 비격자 경계는 제안 근거로 통합 리뷰에 전달

상태: 채택, signal producer는 후속 구현

약 5초 Phase 1 샘플과 5~30초 기계 세그먼트는 coverage·overview용으로만 유지합니다. STT·음성 활동·FFmpeg·Apple Vision 신호는 `boundary-proposal/v1`의 source-relative timestamp와 evidence ID로 합치고, 기존 그룹별 통합 장면-대화 리뷰에 선택 입력으로 전달합니다. proposal은 자동 컷이 아니며 모델은 화면·행동·대화 완결성을 함께 보고 채택하거나 무시합니다. 채택한 시각은 `editorial_beats.source_boundary_proposal_ids`로 역추적합니다. Vision 운영 목표는 약 3fps이고, FFmpeg와 STT는 자체 timestamp 정밀도를 유지하며, 후보 주변 원본 FPS 재검사는 기본 실행하지 않습니다.
