# 결정 기록과 미결 사항

## 확정된 초기 결정

### D-001: 로컬 우선으로 시작

상태: 채택

원본을 외부 서비스에 먼저 업로드하지 않습니다. 인벤토리, 프록시, 음성, 대표 프레임과 기본 색인을 로컬에서 생성합니다. VideoDB나 OpenAI API는 파일럿 결과에 따라 선택적으로 사용합니다.

### D-002: 원본 불변

상태: 채택

원본 영상은 읽기 전용으로 취급합니다. 파생 자료와 출력은 별도 디렉터리에 생성하며 원본 파일 이름 변경, 덮어쓰기, 삭제를 자동화하지 않습니다.

### D-003: STT 단독 색인 금지

상태: 채택

여행 영상은 말이 없는 풍경과 행동이 중요하므로 음성 전사, 대표 프레임, OCR, 촬영 시각, GPS와 품질 지표를 함께 사용합니다.

### D-004: 편집 계획은 구조화 데이터로 보존

상태: 채택

편집 추천은 자유 텍스트만으로 남기지 않습니다. 모든 클립을 `asset_id`, `source_in`, `source_out`, 역할, 선택 이유와 함께 JSON으로 저장하고 OTIO/FCPXML/EDL로 내보낼 수 있게 합니다.

### D-005: MCP는 선택 사항

상태: 채택

초기 파일럿은 직접적인 로컬 도구로 수행합니다. FFmpeg MCP, Resolve MCP, VideoDB MCP는 반복성과 편집기 제어 필요성이 확인된 뒤 도입합니다.

### D-006: 파일럿 우선

상태: 채택

10일치 전체 배치 전에 하루치 또는 30~60분의 다양한 촬영 조건으로 파이프라인을 검증합니다.

### D-007: 전수 타임라인과 편집 후보 분리

상태: 채택

원본의 모든 시간대는 세그먼트 타임라인에 포함합니다. 편집 후보는 그 타임라인에서 파생하며, 후보 개수 제한 때문에 원본의 일부가 검색 불가능해지지 않게 합니다.

### D-008: 모델 호출을 A/B/C 등급으로 제한

상태: 채택

고가치 구간은 상세 분석하고, 반복 구간은 군집 대표만 분석하며, 명백한 불량·중복 구간은 기계 분석만 유지합니다. 사용자가 요청한 구간은 나중에 상세 등급으로 승격할 수 있습니다.

### D-009: 전체 프록시 선생성 금지

상태: 채택

초기 색인은 오디오, 대표 프레임, 장면 경계와 품질 신호로 만듭니다. 저해상도 영상 프록시는 리뷰나 렌더에 필요한 범위만 주문형으로 생성합니다.

### D-010: 모델 입출력은 ID 기반 스키마로 제한

상태: 채택

코덱스에는 연락판, 기존 세그먼트 ID, 제한된 STT와 기계 신호만 제공합니다. 응답의 ID와 타임코드는 입력과 대조하고 자유롭게 만든 범위는 거부합니다.

### D-011: 한국어·영어 STT 후보를 항상 함께 보존

상태: 채택

한국어와 현지 영어가 섞인 여행 영상은 전체 음성을 한국어와 영어로 각각 전사합니다. 기계 점수만으로 한 후보를 삭제하지 않고 장면별로 두 후보를 함께 보존하며, 코덱스가 화면 맥락과 함께 대화 내용을 종합합니다. 언어별 전사는 독립적으로 캐시합니다.

### D-012: 장면 설명과 대표 이미지는 2차 스토리보드로 확정

상태: 채택

1차 연락판은 시간축을 나누고 사건 그룹을 만드는 데 사용합니다. 그룹이 정해지면 내부에서 시간 분포, 시각적 차이와 화질을 반영한 최대 12장 스토리보드를 만들고, 코덱스가 전체 맥락 설명·핵심 순간·최종 대표 이미지를 다시 선택합니다. 기계가 고른 한 장을 최종 대표로 간주하지 않습니다.

### D-013: 웹 리포트는 영상 없이 즉시 생성

상태: 채택

기본 웹 산출물에는 원본이나 프록시 영상을 포함하지 않습니다. 공용 미리보기 덱과 원본 기준 `start/end`만 유지해 리포트 렌더는 즉시 끝나게 합니다. 프록시 생성은 별도의 캐시 가능한 미디어 단계로 분리합니다.

### D-014: 프록시에서 판단하고 원본에 편집 적용

상태: 채택

저화질 프록시는 분석·검토·미리보기 용도입니다. 프록시는 원본과 같은 시작점과 길이를 유지하고, 모든 결정은 `asset_id + source_in + source_out`으로 저장합니다. 최종 컷, 자막과 효과는 이 좌표를 4K 원본에 적용해 렌더합니다.

### D-015: Codex 스킬은 코어 CLI의 얇은 실행 계층

상태: 채택

처리, 검증과 웹 렌더 로직은 일반 CLI와 JSON 계약에 둡니다. 완성 후 만드는 Codex 스킬은 환경 확인, 명령 실행, 연락판·스토리보드 해석과 구조화 리뷰 작성을 순서대로 오케스트레이션합니다. 이렇게 해야 스킬 설치 위치와 무관하게 같은 프로젝트를 재사용하고 테스트할 수 있습니다.

### D-016: 웹 검토 프레임은 기본적으로 HTML에 내장

상태: 채택

Codex 리모트나 다른 컴퓨터에서 상대 경로가 끊겨 이미지가 보이지 않는 문제를 피하기 위해 `render-web`의 기본 자산 모드는 `embed`로 둡니다. 고정된 로컬 디렉터리에서 용량을 줄여야 할 때만 `--assets relative`를 선택합니다. 영상은 내장 대상이 아닙니다.

### D-017: 영상 플레이어는 리포트 전체에 하나만 유지

상태: 채택

각 사건 안에 영상 플레이어를 반복하면 긴 타임라인의 정보 밀도와 스캔 속도가 떨어집니다. 현재는 상단 공용 미리보기 덱만 두고, 프록시가 준비되면 이 위치의 단일 플레이어 또는 데스크톱 PIP로 재생합니다. 모든 타임코드 동작은 같은 플레이어를 제어합니다.

### D-018: 행동과 음성을 같은 편집 판단 행에 결합

상태: 채택

세부 구간마다 원본 `start/end`, 대표 프레임, 화면·행동 해석, 한국어·영어 STT 후보, 무음·품질 신호와 편집 제안을 함께 표시합니다. 제안 상태는 검토 우선순위일 뿐 자동 컷 확정이 아니며, 실제 결정은 시청 확인 후 원본 좌표에 기록합니다.

## 미결 사항

### Q-001: 카메라와 메타데이터

- MP4 메타데이터에서 `DJI OsmoPocket3`를 확인했다.
- GPS, 자이로, 가속도 메타데이터가 있는가?
- 360도 영상 또는 제조사 전용 포맷이 포함되어 있는가?

### Q-002: 미디어 저장소

- 원본은 T7의 `시애틀알래스카` 아래 6개 폴더에서 427개·약 417.59 GiB로 확인했다.
- T7 가용 공간은 약 253 GiB, 내부 데이터 볼륨은 약 50 GiB다.
- 프록시와 프레임을 얼마나 오래 보관할 것인가?

### Q-003: 편집기

- FFmpeg 미리보기만 필요한가?
- DaVinci Resolve, Premiere Pro, Final Cut Pro 중 어느 편집기를 사용할 것인가?
- NLE 프로젝트까지 자동 생성할 것인가, 선택 목록만 넘길 것인가?

### Q-004: 클라우드와 개인정보

- 원본·프록시·음성 각각에 대해 외부 API 전송이 가능한가?
- 타인의 얼굴과 음성을 어떻게 처리할 것인가?
- 위치 정보가 공개용 결과물에 포함되어도 되는가?

### Q-005: 첫 결과물

- 개인 소장 장편, YouTube 본편, Shorts 중 무엇을 먼저 최적화할 것인가?
- 원하는 러닝타임과 편집 템포는 무엇인가?
- 참고할 유튜브 영상이나 편집 스타일이 있는가?

## 다음 결정 시점

파일럿 원본 폴더를 지정한 뒤 읽기 전용 인벤토리를 생성하고, 실제 코덱·총 재생 시간·메타데이터와 저장 공간 요구량을 확인한 시점에 미결 사항을 갱신합니다.
