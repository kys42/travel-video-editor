# `kyungdoc/video-summary` 검토

참고 저장소: <https://github.com/kyungdoc/video-summary>

## 결론

이 저장소를 그대로 포크하기보다는 검증된 파이프라인 패턴을 차용합니다. 참고 프로젝트는 긴 영상을 값싸게 좁혀 편집 후보를 만드는 데 강하고, 이 프로젝트가 원하는 전수 장면 검색에는 별도 계층이 더 필요합니다.

2026-09-01 기준 로컬 검토에서 Python 3.12와 `uv` 환경으로 테스트 `160 passed, 67 subtests`를 확인했습니다.

## 차용할 아이디어

- 전체 프록시 없이 로컬의 저비용 신호부터 계산
- SQLite 기반 단계별 상태와 캐시
- 임시 파일 완성 후 원자적 교체
- LLM에는 임의 타임코드가 아니라 사전에 만든 후보 ID만 선택하게 하는 경계
- JSON 스키마와 타임코드 범위의 엄격한 검증
- 선택된 구간만 순차 렌더
- 선택적 연락판으로 장면 검토
- 기존 SRT sidecar 재사용

## 그대로 쓰지 않을 부분

- 후보 장면만 만들면 영상 전체의 장면 목록이 되지 않음
- 밝기·대비·움직임 중심 신호만으로 장소·행동·사건을 설명할 수 없음
- 후보 수 상한은 긴 여행에서 후반부나 조용한 중요 장면을 누락시킬 수 있음
- OCR, GPS, 중복 군집, 개인정보, 의미 검색, 리뷰 UI가 별도 필요
- 한 번의 평면적인 계획보다 세그먼트→파일→하루→여행 계층이 필요

## 적용 방향

참고 프로젝트의 `후보 생성 → 계획 → 검증 → 렌더` 구조 앞에 `전수 세그먼트 → 구조화 주석 → 검색 타임라인`을 추가합니다. 후보는 타임라인에서 파생되는 편집용 뷰이며, 원본 색인의 대체물이 아닙니다.

라이선스와 출처를 확인하기 전에는 소스 코드를 복사하지 않습니다. 우선 아키텍처 아이디어만 독립적으로 구현합니다.
