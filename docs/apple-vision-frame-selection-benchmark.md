# Apple Vision 대표 프레임 벤치마크

측정일: 2026-09-03

## 목적

Apple Vision의 `CalculateImageAestheticsScoresRequest`와
`GenerateImageFeaturePrintRequest`를 여행 영상 대표 프레임 후보 생성에 사용할 때
샘플링 밀도에 따른 시간·메모리 비용과 실제 선택 품질을 확인한다.

## 측정 환경과 소스

- macOS 26.6.2, Apple Silicon Mac mini
- Swift 6.2.3, Apple Vision `VideoProcessor`
- 처리 입력: `cam2-0825/DJI_20260826073937_0009_D.mp4`
- 입력 사양: 1920×1080 H.264, 29.97fps, 200.5003초, 150,173,568바이트
- 4K 원본: `cam2-0825/DJI_20260826073937_0009_D.MP4`
- lineage: `work/lineage/DJI_20260826073937_0009_D.apple-vision-benchmark.json`
- 교차 검증 lineage: `work/lineage/DJI_20260826073820_0008_D.apple-vision-benchmark.json`,
  `work/lineage/DJI_20260826111739_0034_D.apple-vision-benchmark.json`
- 벤치마크 실행 파일의 직접 리소스는 `/usr/bin/time -l`로 측정했다. Core ML,
  VideoToolbox 또는 시스템 서비스가 사용하는 별도 가속기 리소스는 이 수치에 전부
  잡히지 않을 수 있다.
- 같은 파일을 반복 실행했으므로 후속 실행에는 macOS 파일 캐시 효과가 있을 수 있다.
  첫 번째 5초 간격 실행도 6.57초였으므로 결론을 바꿀 정도의 차이는 관찰되지 않았다.

경과 시간, 프레임 처리율과 실시간 배수는 `/usr/bin/time -l`의 프로세스 전체
wall-clock 시간과 `ffprobe`로 확인한 실제 재생 길이를 기준으로 계산했다. 도구가
기록하는 JSON도 `AVURLAsset`의 실제 재생 길이를 별도 필드로 보존한다.

0.25초 간격까지는 샘플 수를 늘려도 전체 영상을 한 번 디코딩하는 약 6초의 비용이
지배적이었다. FeaturePrint를 함께 요청한 추가 비용도 이번 단일 실행에서는 측정
오차 범위였다. 0.1초부터 추론량에 따라 시간이 늘기 시작했으며 사실상 30fps 전
프레임을 처리해도 원본 재생 시간보다 약 6배 빨랐다.

0.25초 분석 뒤 31개 세그먼트의 선택 프레임 JPEG를 추출하고 시트를 만드는 데는 약
2초가 추가됐다. 따라서 이 샘플에서 `0.25초 Vision 분석 + 최종 이미지만 추출`은 약
8초 규모였다.

0.25초 설정을 다른 프록시 두 개에도 적용했다.

|---|---|---:|---:|---:|---:|---:|
| `0008` | 1080p, 29.97fps | 58.06초 | 233+233 | 1.92초 | 30.24× | 45.1MB |
| `0034` | 1080p, 59.94fps | 109.48초 | 438+438 | 6.44초 | 17.00× | 44.5MB |

짧은 30fps 클립에서도 약 30배속이 재현됐다. 60fps 클립은 요청 샘플 수가 아니라
원본 디코딩 프레임 수가 두 배이므로 처리 속도가 약 17배속으로 낮아졌다. 메모리는
두 경우 모두 약 45MB였다.

완성된 프록시 390개의 manifest상 총 길이는 약 16.59시간이다. 이번 1080p H.264
샘플 비율을 단순 적용하면 0.25초 간격 분석은 약 31분, 30fps 전 프레임 분석은 약
2.7시간이다. 실제 총 시간은 영상별 FPS, 길이, 동시 작업, 캐시와 프로세스 시작
비용에 따라 달라지므로 배치 적용 전 여러 코덱·FPS 샘플로 다시 측정한다.

## 선택 품질 관찰

- 0.25초 간격은 기존 5초 간격에서 놓친 더 안정적인 얼굴, 음식 트럭, 병 음료와
  화로 구도를 잘 발견했다.
- 30fps 전 프레임은 0.25초 결과보다 일부 장면에서 점수가 조금 더 좋은 순간을
  발견했지만, 육안상 개선 폭은 처리시간 증가만큼 크지 않았다.
- 미학 점수만으로 영상 전체 상위 프레임을 고르면 같은 인물의 밝은 얼굴 컷에
  후보가 몰렸다. FeaturePrint만으로도 서사적 다양성이 충분히 보장되지 않았다.
- `125초`의 음료 수령 행동은 기존 의미 기반 대표 프레임이 정확히 담았지만,
  Vision은 같은 5초 세그먼트 후반의 더 깨끗한 정지 화면을 더 높게 평가했다.
  따라서 미학 점수는 행동·대화·장면 의미를 대체할 수 없다.

## 권장 파이프라인

기본 밀도는 **0.25초(초당 4장)** 로 한다. 이 샘플에서는 5초 간격과 비용이 거의
같으면서 순간 선택 폭이 20배 늘었고, 30fps 전 프레임 대비 육안 품질 손실이 작았다.

1. 프록시 전체를 0.25초 간격으로 한 번 디코딩해 미학 점수와 FeaturePrint를 함께
   계산한다.
2. 기존 scene/segment/event/STT 시간 범위는 유지한다. Vision이 경계를 바꾸거나
   의미 기반 대표 프레임을 자동으로 덮어쓰지 않는다.
3. 각 범위에서 `의미 기반 앵커 + 미학 상위 후보 + 전후 경계 후보`를 만들고,
   시간 간격과 FeaturePrint로 중복만 제거한다.
4. 손에서 물건을 받는 행동, 표정 변화, 짧은 리액션처럼 빠른 이벤트는 해당 구간
   ±0.5~1초만 원본 FPS로 재분석한다.
5. 최종적으로 장면당 1~3장만 contact sheet에 넣어 Codex가 의미와 편집 가치를
   판단한다. Vision 전체 점수는 로컬 메타데이터로 보존하되 모델에 보내지 않는다.

이 구조라면 계산량은 가볍게 유지하면서도 5초 고정 샘플보다 좋은 순간을 찾을 수
있고, 미학 모델이 결정적 행동을 지워버리는 실패도 피할 수 있다.
